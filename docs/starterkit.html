Unity 6 · Starter Kit

Unity 프로젝트를 한 번에 세팅하는 스타터 킷

Unity CLI, Pipeline, Claude Code 연결, Multiplayer Center 기본 설정을 명령 하나로 적용합니다. 새 프로젝트마다 설치 방법을 다시 검색하지 않아도 됩니다.

빠른 시작

아래 세 가지가 이미 설치되어 있다고 가정합니다. Unity Hub와 Unity 6 Editor(6000.x), Git, Claude Code. VS Code도 함께 쓰는 환경을 기준으로 했습니다.

1. 사전 점검

powershell -ExecutionPolicy Bypass -File .\scripts\new-project.ps1 -CheckOnly

2. 프로젝트 생성

생성 전에 Unity 계정 로그인 상태를 확인하고, 로그인되어 있지 않으면 브라우저 로그인을 엽니다. 3D와 2D 중 하나를 고릅니다.

powershell -ExecutionPolicy Bypass -File .\scripts\new-project-3d.ps1 -Name MyGame -Path C:\UnityProjects -Open
powershell -ExecutionPolicy Bypass -File .\scripts\new-project-2d.ps1 -Name MyGame2D -Path C:\UnityProjects -Open

3. Multiplayer Center 설정

생성할 때 services와 netcode 패키지 버전을 기록하고 헤드리스로 URP 머티리얼을 업그레이드합니다. 첫 Editor 실행 때 Multiplayer Center 패키지를 설치하고 창을 엽니다. 게임 종류를 고르면 추천 패키지가 설치됩니다.

  • 사전 점검Unity 6 Editor, Unity CLI, git, claude 확인, Unity 로그인 상태
  • 프로젝트 생성2D(Universal 2D) 또는 3D(Universal 3D) 템플릿, Git 초기 커밋, Pipeline, Claude Code 연결
  • 멀티플레이어services와 netcode 버전 기록과 헤드리스 URP 준비, 첫 실행 때 Multiplayer Center 설치와 창 열기

옵션

옵션기본값설명
-Name필수프로젝트 폴더 이름
-Path필수상위 폴더. 짧은 경로를 권장합니다.
-Editor설치된 6000.x 중 최신예: 6000.3.10f1
-Templatecom.unity.template.urp-blanknew-project.ps1 전용. 3D 래퍼는 urp-blank, 2D 래퍼는 universal-2d를 씁니다. 다른 템플릿 예: com.unity.template.3d
-SkipGitoffGit 초기화를 건너뜁니다.
-Lfsoffpsd, fbx, wav, png 등 큰 바이너리를 Git LFS로 추적합니다.
-SkipMultiplayeroff멀티플레이어 설치 스크립트 복사와 헤드리스 준비를 건너뜁니다.
-SkipLoginoff생성 전 Unity 로그인 확인을 건너뜁니다.
-Openoff끝나면 Unity Editor를 엽니다.
-CheckOnlyoff사전 점검과 로그인 상태만 확인하고 끝냅니다.

구성

claude-unity-starterkit/ ├── README.md ├── scripts/ │ ├── new-project.ps1 전체 흐름 (로그인 확인 → 생성 → ... → 헤드리스 준비) │ ├── new-project-3d.ps1 3D(Universal 3D) 래퍼 │ └── new-project-2d.ps1 2D(Universal 2D) 래퍼 └── template/ 생성되는 프로젝트에 복사되는 파일 ├── CLAUDE.md Claude Code 작업 지침 ├── .claude/settings.json unity 명령 허용 목록 ├── .gitignore 공식 파일 다운로드 실패 시 대체용 └── Assets/Editor/StarterKit/ ├── MultiplayerPackageInstaller.cs Multiplayer Center 설치와 창 열기 └── ProjectSetup.cs 헤드리스로 URP 머티리얼 업그레이드

스크립트 흐름

  1. 사전 점검: unity, git, claude, 설치된 Unity 6 Editor
  2. unity projects create로 프로젝트 생성 (--no-cloud)
  3. Git 초기화, 공식 Unity .gitignore 적용, 초기 커밋, Library/ 미포함 확인
  4. unity pipeline install --project-path
  5. CLAUDE.md, .claude/settings.json 복사, unity skill install claude-code --local
  6. 멀티플레이어 설치 스크립트 복사
  7. manifest.json에 services.multiplayer, netcode.gameobjects의 호환 버전 기록 (Burst를 끌어오는 패키지)
  8. unity run <프로젝트> -- -executeMethod ProjectSetup.Run으로 헤드리스 실행해 URP 머티리얼 업그레이드. Editor 창을 열기 전에 끝냅니다.

자동 vs 수동

자동으로 되는 것

  • Unity 6 프로젝트 생성
  • Git 저장소와 초기 커밋
  • Unity Pipeline 패키지
  • Claude Code 지침, unity-cli 스킬, 권한 설정
  • 멀티플레이어 패키지 버전 기록과 URP 머티리얼 업그레이드 (생성 시 헤드리스로 처리)
  • Multiplayer Center 패키지 설치와 창 열기 (첫 Editor 실행 때)

직접 해야 하는 것

  • Multiplayer Center에서 게임 종류 선택
  • Unity Services에 프로젝트 연결 (Project Settings > Services, 메뉴 위치는 버전마다 다를 수 있음)
  • 필요하면 로그인과 라이선스 확인 (unity auth status, unity license status)

Multiplayer Center

설치되는 패키지는 세 개이며, 각 패키지의 최신 호환 버전을 설치합니다.

  • com.unity.multiplayer.center: 게임 종류에 맞는 패키지를 추천하고 설치합니다.
  • com.unity.services.multiplayer: 세션, 로비, 매치메이킹 API
  • com.unity.netcode.gameobjects: 실시간 동기화 (NGO)

Multiplayer Center 창은 Window > Multiplayer > Multiplayer Center에서 확인했습니다. 설치 스크립트는 첫 실행 때 Multiplayer Center를 설치하고 이 창을 엽니다. 다시 설치하려면 Tools > Starter Kit > Install Multiplayer Packages를 실행하세요.

services와 netcode는 생성 시 manifest.json에 버전을 적어 두고 헤드리스 실행으로 미리 설치합니다. 배치 모드는 비동기 설치를 기다리지 못해서 이 방식을 택했습니다. Burst 업데이트가 Editor 창을 연 뒤에 일어나지 않도록 하기 위해서입니다.

검증 상태

Unity 6000.3.10f1, Windows 11에서 전체 스크립트를 한 번 실행해 확인했습니다.

  • 확인됨사전 점검 통과
  • 확인됨프로젝트 생성, Git 초기 커밋, Library/ 미포함
  • 확인됨com.unity.pipeline 설치
  • 확인됨.claude/skills/unity-cli 설치
  • 확인됨설치 스크립트를 헤드리스 Editor로 컴파일, error CS 없음
  • 확인됨Editor 실행 중 설치 스크립트로 최신 호환 버전 설치: multiplayer.center 1.0.1, services.multiplayer 2.4.1, netcode.gameobjects 2.13.3
  • 확인됨전체 스크립트로 새 프로젝트를 만든 뒤 헤드리스 단계 실행: services.multiplayer 2.4.1, netcode.gameobjects 2.13.3이 lock에 기록되고 Burst 1.8.29로 올라감, ProjectSetup.Run 종료 코드 0
  • 미확인처음 Editor 창을 열 때 "URP material upgrade"와 "Burst Package Update Detected" 창이 뜨지 않는지 (GUI에서 확인하지 못함). 테스트 프로젝트에는 업그레이드할 머티리얼이 없어서 머티리얼 업그레이드 효과도 확인하지 못함
  • 미확인설치 후 Multiplayer Center 창 자동 열기, Multiplayer Center 선택 흐름과 Services 연결
  • 미확인공식 Unity.gitignore 다운로드 (네트워크 의존, 실패 시 대체 파일 사용)

주의

  • 긴 경로에서 패키지 DLL 경로 오류가 날 수 있습니다. 테스트 중 보인 오류는 긴 임시 경로 때문으로 보이며, 원인은 확인하지 않았습니다. 짧은 경로에 만드세요.
  • 생성 전에 로그인 상태를 확인하고 로그인되어 있지 않으면 브라우저 로그인을 엽니다. 건너뛰려면 -SkipLogin을 붙입니다. 문제가 생기면 unity doctor --format json으로 인증, Editor, 최근 오류를 한 번에 볼 수 있습니다.
  • 이 킷의 .gitignore는 대체용입니다. 공식 Unity 템플릿을 우선 사용합니다.
  • 이전 버전 킷으로 만든 기존 프로젝트에는 이 변경이 적용되지 않습니다. 해당 프로젝트에 ProjectSetup.cs를 복사한 뒤 unity run <프로젝트 경로> -- -executeMethod ProjectSetup.Run을 실행하면 URP 머티리얼 업그레이드를 미리 처리할 수 있습니다. Burst 확인 창은 한 번 더 뜰 수 있습니다.
